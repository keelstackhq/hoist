# hoist M1 (read-only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `hoist` binary that infers what a hull repo needs, reads the live GitHub and Cloudflare state, and reports it with `explain`, `plan`, `check` and `auth check`, without writing anything.

**Architecture:** Three layers, each testable alone: (1) offline inference turns repo files plus `hoist.toml` into a `Desired` model; (2) readers turn API responses into a `Live` model; (3) pure `diff` and `verify` functions turn (Desired, Live) into report items. Commands only wire layers together and render one `Report` as a table or one JSON object.

**Tech Stack:** Rust 1.97, edition 2024. Crates (versions checked on crates.io 2026-10-16, pin exactly): `clap 4.6.7` (derive), `serde 1.0.229` (derive), `serde_json 1.0.154`, `toml 1.1.8`, `yaml_serde 0.10.7`, `jsonc-parser 0.34.0` (feature `serde`), `regex 1.13.1`, `ureq 3.4.2` (rustls, the default), `thiserror 2.0.21`. Dev: `insta 1.49.0` (features `json`), `assert_cmd 2.2.2`, `predicates 3.1.4`, `tempfile 3.27.0`, `tiny_http 0.12.0`. Ask before adding any other crate.

**Spec:** `docs/superpowers/specs/2026-10-16-hoist-design.md` (§3 CLI, §4 inference, §5 hoist.toml, §6 resources, §7.1 plan, §7.4 verification, §8.1 credentials, §8.4 unknown, §8.5 never leaking, §11 testing).

## Global Constraints

- Names: repo `keelstackhq/hoist`, binary `hoist`, Cargo package `keel-hoist`, lib `hoist`.
- Exit codes: `0` in sync / success · `1` drift, a failed write or a failed verification · `2` human step pending · `3` usage, config or auth error (message says how to fix it). clap usage errors also exit 3.
- `--json` prints exactly one object on stdout: `{ "version": 1, "command", "ok", "exit_code", "items": [ { "area", "kind", "key", "action", "reason", "source", "verify" } ], "human_steps": [ { "id", "title", "url", "status" } ] }`. Logs go to stderr.
- Actions: `create`, `update`, `ok`, `drift`, `pending`, `unknown`.
- M1 never sends a request other than GET (and the token verify GET). A test asserts it (Task 7).
- Secret values never appear in stdout, stderr, JSON or logs; tokens come from env or `gh auth token`, never argv.
- `rustls` only, no OpenSSL; `#![forbid(unsafe_code)]`.
- API base URLs: `HOIST_GITHUB_API` (default `https://api.github.com`), `HOIST_CLOUDFLARE_API` (default `https://api.cloudflare.com/client/v4`). Tests point them at the fake server.
- Ruleset name `hoist: default branch`; minted-token prefix `hoist:` (M2, not read in M1).
- `hoist.toml` unknown keys are an error (exit 3, names the key and file).
- Fast checks before every commit: `cargo fmt --check && cargo clippy --all-targets --locked -- -D warnings && cargo test`.

## Review Focus

1. **No GitHub remote** (no `origin`, or a GitLab/self-hosted URL): exit 3 with "set an `origin` remote pointing to github.com"; never panic. Test in Task 3.
2. **Malformed repo files** (invalid YAML in a workflow, invalid JSONC in `wrangler.jsonc`, invalid TOML in `hoist.toml`): exit 3 naming the file and the parser's line; never panic. Tests in Tasks 2, 4, 5.
3. **Pagination** (more than 30 secrets, environments or rulesets): readers follow `Link: rel="next"`; a missing item on page 2 must not show as `create`. Test in Task 8.
4. **Token without permission** (403 on rulesets or secrets): that resource is `unknown` with the reason "token lacks <permission>"; the rest of the plan still runs and `check` does not exit 3. Test in Task 8.
5. **Classic branch protection instead of a ruleset**: the ruleset item is `create` and its reason says "classic branch protection exists on `main`; M2 decides migration", so nobody thinks the branch is unprotected. Test in Task 8.
